05
بيانات vs إعدادات

Store Data vs Merchant Configuration

من أهم الفروق في Twilight
Store Data
ما الذي يحتويه المتجر؟
  • Product Name
  • Price
  • Images & Availability
  • Store Information
  • Customer Data
vs
Merchant Configuration
كيف ضبط التاجر الثيم؟
  • Show breadcrumbs?
  • Primary color
  • Section title
  • Banner image
  • Show/Hide theme options

مثال عملي

المتجر عنده:
Product: Ethiopian Coffee
Price: 80 SAR
والتاجر اختار في الثيم:
Show Rating = true

الاتنين ممكن يدخلوا في عملية الـrender، لكن مصدرهم ومسؤوليتهم مختلفين.

06
Theme Engine

Twilight Engine — ليه موجود؟

Twilight runs the Theme.
مش الثيم نفسه · مش Salla CLI

Conceptually يستخدم:

  • Store Data
  • Merchant Configuration
  • Theme Templates

ليه Twilight ضروري؟

المتصفح لا يفهم Twig syntax مثل:

{% extends "layouts.master" %}
{% if product.available %}
{{ product.name }}

الـTwig templates لازم يتحولوا لـHTML قبل ما يوصلوا للمتصفح.

08
Directory Responsibilities

مسؤولية كل مجلد

layouts/

Shared page skeletons — الهيكل المشترك بين Pages متعددة (Header, Footer, Shell)

pages/

Templates for specific storefront pages — Home, Product, Cart, Blog…

components/

Reusable / organized Theme UI pieces — Product Card, Header, Footer sections

assets/js/

Browser-side interactions — Event listeners, Menus, Drawers, Modals, DOM interactions

assets/styles/

Styling — Typography, Colors, Spacing, Responsive, RTL/LTR, Animations

locales/

Translation strings — ar.json, en.json — لكن RTL layout → styles concern أيضًا

⚠️ Feature واحدة = أكثر من Layer — مثلاً Mega Menu: Header Component + JavaScript + Styles + Theme Settings + Localization
09
Template Inheritance

Layout vs Page

التدرج
Page (index.twig)
↓ extends
Layout (master.twig)
النتيجة المركّبة
Header (shared from layout)
[ Page Content Slot ]
الـPage تملأ هنا
Footer (shared from layout)
ليه؟

بدون Layout:

  • نكرر Header في كل Page
  • نكرر Footer في كل Page
  • نكرر Global assets
  • أي تغيير global = تعديل كل ملفات

مع Layout inheritance:

  • Less duplication
  • Clear shared structure
  • Easier global changes
  • Better separation
10
Twig Blocks

master.twig — يعني إيه Block؟

<!DOCTYPE html>
<html><head>...</head>
<body>

  {% component 'header.header' %}

  <main>
    {% block content %}
    {% endblock %}
  </main>

  {% component 'footer.footer' %}

</body></html>
Block = Named Slot
Customization point داخل Template Inheritance system

Block ≠ Component

Block
Slot — حاجة فاضية تتملى
Component
قطعة UI جاهزة ومكتملة

مش كل Page لازم تستخدم master.twig

ممكن يكون عندك layouts مختلفة لـPage families ذات structures مختلفة.

layouts/master.twig
layouts/customer.twig
11
Home Page Trace

Trace الـHome Page — خطوة بخطوة

User opens Home
↓
Twilight resolves Home page template
↓
src/views/pages/index.twig
↓
index.twig extends layouts.master
↓
master.twig provides shared shell
↓
index.twig fills:
content → Home content
scripts → home.js
↓
Twig Rendering → HTML output
↓
Browser
{% extends "layouts.master" %}

{% block content %}
  {% component home %}
{% endblock %}

{% block scripts %}
  <script src="home.js"></script>
{% endblock %}

app.js vs home.js

master.twig → app.js (global behavior)
index.twig → home.js (Home-specific)

الفكرة هي Scope — مش أسماء ملفات إجبارية.

12
Theme Configuration

twilight.json — الملف الأهم

twilight.json
│
├── Theme Information
│ ↓
│ "What is this theme?"
│
├── settings
│ ↓
│ "Theme-level configurable options"
│
├── features
│ ↓
│ "Predefined Twilight features declared"
│
└── components
↓
"Custom merchant-configurable components"
├── path → Twig implementation
└── fields → Merchant config

settings

Theme-level/global configuration — قيم يضبطها التاجر للثيم كله

show_sale_badge: true
primary_font: "Cairo"

features

Predefined Twilight capabilities — الثيم يُعلن أنه يدعمها حسب الـschema الرسمي

components

Custom components يعرّفها Developer الثيم — مع fields قابلة للضبط من التاجر

13
Configuration vs Rendering

Component Definition vs Twig File

هنا أهم فكرة في اليوم
twilight.json
Configuration / Schema / Declaration

يجاوب على: ما هو الـComponent؟ فين الـTwig؟ إيه الـfields القابلة للضبط؟

≠
Twig Component File
Rendering Implementation

يجاوب على: كيف يتم عرض الـComponent؟ إيه الـmarkup؟

مثال: Promo Banner

twilight.json
{
  "name": "Promo Banner",
  "path": "home.promo-banner",
  "fields": [
    "title", "image"
  ]
}
components/home/promo-banner.twig
<section>
  <h2>{{ component.title }}</h2>
  <img src="{{ component.image }}">
</section>

الـpath هو حلقة الربط بين الـjson definition والـTwig file

14
Common Mistakes

أخطاء لازم تتجنبها

خطأ ١ Theme = Store
Store = Data · Theme = Presentation
خطأ ٢ Twilight = Theme
Twilight = Theme Engine · Theme = Files executed within Twilight
خطأ ٣ Salla CLI = Runtime
CLI = Dev tooling فقط · Runtime = Salla/Twilight + Active Theme
خطأ ٤ Page = Layout
Layout = Shared shell · Page = Specific content template
خطأ ٥ Block = Component
Block = Template inheritance slot · Component = Reusable UI unit
خطأ ٦ Theme Component = Salla Web Component
Theme/Twig Component = template-side · Salla Web Component = Browser Custom Element
خطأ ٧ twilight.json = UI file
twilight.json = Configuration/Schema · Twig = Rendering Implementation
خطأ ٨ Global = كل حاجة في master.twig
Global scope → inspect shared composition → ضع كل responsibility في الـlayer المناسبة
